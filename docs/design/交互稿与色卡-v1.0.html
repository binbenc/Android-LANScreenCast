01

设计推导：从第一性原理出发

投屏工具的本质只有一句话：让大屏出现我手机上的画面，并且我随时能让它停下。界面的每个元素都必须服务于这句话，否则就是噪音。

行业惯例（隐性假设）底层事实推导出的设计
首页是功能宫格、推荐位用户打开 App 只为一件事；选项越多决策越慢（Hick：T ∝ log₂(n+1)）首页即设备列表，唯一主操作 = 点设备。可信设备 3 次点击完成投屏
搜不到设备 = 一直转圈组播失败是网络拓扑问题，等待不会自愈；用户分不清“还在找”和“找不到”T+3s 给替代路径（扫码 / 投屏码），T+10s 给网络诊断；每个状态都有出口
安全 = 每次都弹确认威胁来自“陌生 + 不在场”；对熟悉设备反复确认只会训练出习惯性点击首次 PIN 证明在场，之后可信设备免确认；TV 确认弹窗默认焦点在“拒绝”
品牌色越鲜艳越好投屏期间注意力在内容上，UI 只是过渡；大屏高彩度 UI 会与内容争夺注意并造成眩光低彩度单一主色相 + 中性灰阶；语义色只在状态变化时出现
延迟、码率是工程信息，不给用户看“卡不卡”是主观感受，没有数字就无法判断该怪网络还是怪设备，也不知道该调什么状态胶囊显示 ms 数值 + 色阶 + 文字等级（三重编码，色弱可用）

不可违背的基础约束

  • 认知：工作记忆约 4±1 个组块 → 每屏 1 个主操作、≤2 个次操作。
  • 设备：手机 360 dp 宽、触控目标 ≥48 dp；TV 960×540 dp、观看距离约 3 m、只有方向键 / 确定 / 返回 / 菜单。
  • 业务：北极星 = 60 秒内首次投屏成功率 ≥90%；最大流失点是“搜不到”。
  • 平台：Android 14+ 每次会话重新授权录屏；不申请定位 → 不能显示 Wi‑Fi 名称；不申请悬浮窗。

投屏中，界面在任何时刻必须回答 4 个问题

  • 连着谁？ 设备名 + 协议 + 加密状态
  • 连得好吗？ 延迟 ms + 色阶等级 + 码率
  • 出问题怎么办？ 原因 + 系统已经在做什么 + 用户能做什么
  • 怎么停？ App 内 / 通知 / 快捷图块，三处同一个动作

四条品牌形容词落地为可检查的规则：安静 = 单主色相、无渐变装饰；可信 = 承诺写可验证的事实；克制 = 语义色只表达状态；专业 = 数字用等宽数字并带单位。

品牌主色与 Material 3 色彩角色

主色 + 两个辅助色相 + 中性灰。表面色带极轻的主色倾向（蓝灰），让整个界面有统一的“温度”而不显得廉价纯灰。

BRAND PRIMARY · 港湾蓝 HARBOR BLUE
#2F5A82
HSL 209° · 47% · 35%　深色模式 #A2C9F0

为什么是这个颜色

  • 可信：蓝色相是跨文化研究中与“可靠、安全”关联最稳定的色相，也是系统级工具（设置、网络）惯用色相，用户不需要重新学习它的含义。
  • 安静：饱和度压到 47%、明度 35%，去掉“营销蓝”的亮度刺激；与乐播类产品常见的高饱和红 / 橙形成气质上的反差。冷色在视觉上“后退”，不抢投屏内容的注意力。
  • 科技：色相落在 209°（偏青的蓝），带一点“信号 / 通讯”的联想，又避开 230°+ 的紫蓝与霓虹感。
  • 省色值：在白底上对比度约 7.2:1（AAA），同一个颜色既能做按钮底色也能直接做文字链接，减少需要维护的 Token 数量。
  • TV 深色：深色模式取同色相高明度 #A2C9F0，在大面积深底上只承担焦点光环与强调，避免大屏眩光。

v1.0.3		未聚焦：同“不可用”（surfaceContainer 底 + outline 字）；可以获得焦点，聚焦时按普通焦点态反相 + 外环 + 光晕；聚焦即在所在面板的说明位置写出原因，按下每次都给出原因提示（不去重）。文字本身须写明不可用（如“方向键（对方不支持）”），不靠颜色“不可用”默认不可聚焦，是因为用户无事可做；但“对方系统版本不支持”这类项用户需要知道原因——不可聚焦就永远读不到说明。只用于“需要说明原因”的项；冷却等“稍后自然可用”的项仍用不可聚焦的“不可用”

双指缩放会在松手后执行对方手机会按两指的变化缩放一次

      

      
F23 CPINCH 宏R07

        
本质
双指缩放是“松手后对方一次性执行”，不是实时跟手（对方手机按起止间距合成一次两指手势）。从按下到画面变化要等：捏合本身 + 回放时长（100–800 ms）+ 链路约 70 ms + 一帧。这段时间画面完全不动，用户会以为没识别到，越捏越用力或重复捏，结果缩放两次。所以本地反馈只回答一件事：“两根手指被识别了 / 已经发出去了”，不预告结果。

        
状态

          
按住：两指各一个 44 dp 空心环跟手（白环 2 dp + 外侧 1 dp 黑描边 35%，无填充；与单击涟漪同一套笔触，但不扩散、不填充，表示“正按着”）。不画两指连线。

          
松手（已发送）：任一手指抬起即发送；两环停在最后位置、变为实心（白 40%），在本次回放时长 dur（100–800 ms）内线性淡出——淡出结束≈对方动画结束，把等待“填满”。

          
变化 <5%（双指轻点 / 双指平移）：不发送，空心环 150 ms 快速淡出，不做实心态——“识别到了，但不构成缩放”。不另提示。

          
关闭动画（动画缩放 = 0 / 减少动态效果）：按住时静态空心环跟手（位置跟随不是动画）；松手后实心静态环显示 300 ms 后直接消失；<5% 时直接消失。

        

        
提示
  • 首次：本机第一次发出双指缩放后，出 R08 中性提示“双指缩放会在松手后执行 / 对方手机会按两指的变化缩放一次”（图示；每次安装只出一次）——纠正“实时跟手”的预期。
  • 落在黑边上：任一手指按在画面外的黑边上时不开始缩放（已开始的单指手势仍取消），提示“双指需在画面内 / 两根手指都要放在对方画面上”，每次控制一次（被动触发去重）。
  • 对方版本不支持：不画实心态，提示见 R08 C 期组，每次控制一次。
  • 暂停中：双指同单指，整个手势被吃掉并按暂停原因提示一次。

        
不做预览
不在本地缩放画面：① 对方应用怎样响应缩放无法预测（不可缩放、按对数缩放、触发系统放大），预览与结果常不一致；② 预览要在松手时撤回，而真实缩放 100–900 ms 后才到，会出现“放大 → 弹回 → 再放大”的二次运动，比没有反馈更糟；③ 镜像画面代表对方整块屏幕（含状态栏），整体放大会破坏“画面 = 对方屏幕”的心智模型，也与坐标换算冲突。

        
鼠标
外接鼠标 Ctrl + 滚轮 = 捏合（向上放大，每格 ×1.25，50 ms 内合并），以指针为中心；合并后发出时在指针处显示一次实心静态环 300 ms。

        
读屏
环与提示为纯视觉反馈，不进无障碍树；提示条按 R08 规则播报。

结构
  • 标题“输入到 ××”（×× = 对方设备名，heading）：说清文字去哪。

结果
  • 点“输入”后对话框关闭，文字整段送出；成功不另提示（对方画面里能看到结果）。

TV

读屏
标题为 heading；文本框标签“要输入的文字”；计数不设 liveRegion（逐字播报干扰输入）。
